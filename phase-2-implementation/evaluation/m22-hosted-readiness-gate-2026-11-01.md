## Narrow boundary and authorization finding

`backend/tests/run_groq_development.py::_six_campaign` is a *development* sequence, not a prospective campaign API. It calls the existing typed Configuration/Pricing, Fulfillment and M2.1 Credit/Policy/Routing continuations in order, constructing **separate** stage manifests as it goes. Typed and M2.1 sender paths check their own approval artifact/owner, checkpoint and receipts; `hybrid_send_reservation.claim_and_call` is exclusive and never retries an uncertain send. Existing free-tier rate coordination may wait or stop before a send. Those local records validate a bounded stage send but **do not authenticate an independent authorizer of a whole, predeclared M2.2 campaign**. The development CLI accepts a credential/environment opt-in and even creates some of its stage approval artifacts inside the run. Merely wrapping `_six_campaign` in `OfflineCampaign.execute_offline`, passing `authorized=True` or supplying a key would invent authority. A privileged owner could replace a local digest and its file. There is no trusted external principal, signature/immutable owner-published approval or independently attested all-stage budget/case approval contract in the repository.

`backend/dealdesk_phase2/m22_hosted_readiness.py` therefore defines a **read-only, non-sendable** prospective preflight, not a new hosted sender. `inspect_prospective_case` requires a frozen campaign with write-once eligible preflight, exact Phase 1C/Phase 2 and case identities, source/bundle/as-of/run, six original fixed slots and a fresh pinned adapter verification. It rejects a pre-existing start marker/uncertain run. It checks a frozen six-stage prompt-*version* plan digest and Groq model against declared contracts; this digest alone is **not** a complete hash of actual system instructions, request bodies or quota. It does not create a start marker or reserve a provider attempt. `run_hosted_prospective` **always raises before inspecting any callback/credential**, even if passed an `authorized` flag. There is no config switch to enable it. Historical hosted runs cannot be enrolled retrospectively; the old CLI remains unchanged by default. The earlier offline entrypoint remains available for fake-transport tests only.

**Material gate requiring Ali/security/Phase 1C owner review before a sendable implementation:** choose a trusted identity and independently preserved campaign-approval source, decide who attests case/cohort/source/model/prompt/version/budget/quota and file ownership, bind six stage-specific immutable manifests to one pre-approved campaign digest, then prove the trusted pre-send gate cannot be bypassed via old development pathways. Alternatives: (a) existing owner-local approval files alone — **rejected**, no independent actor authentication or immutable external approval; (b) human-issued independently stored signed/verified approval with existing Python/PostgreSQL where feasible — **recommended for detailed design**, key management, retention and security review needed; (c) new auth service/database — possible security/ops/cost/learning implications, **not approved**. This document does not choose or install infrastructure, assign authorization roles, provision credentials, authorize a free-tier campaign or alter hosted sender contracts. After an approved contract, integrate gate *before first provider reservation* and recheck per-stage model/prompt/budget identities against independently signed manifest; retain the exclusive start/no-replay and existing sender receipts. No automatic retry after restart.

## Timing and scoring boundaries

The development six-stage helper accepts an **optional** measurement recorder (default `None`, so historical CLI behavior is unchanged). When tests supply it, monotonic spans cover *combined* Configuration+Pricing, Fulfillment, and *combined* Credit+Policy+Routing, including exceptions and waiting inside each call. `OfflineCampaign` separately measures end-to-end wall time in its write-once sidecar; `m22_capture` reports present provider-returned usage and per-attempt elapsed, while `timing_observation` preserves missing per-specialist Configuration, Pricing, Credit, Policy, Routing, wait and checkpoint durations as `null` unless **independently measured**. A combined span must not be copied into six separate specialist metrics; no subtraction claims provider processing time, graph/checkpoint overhead or cost. Actual free-tier rate wait cannot be isolated from a combined stage without reviewed instrumentation in the coordinator; typed-final provider elapsed remains absent. No parallel execution is introduced. Full six stage-specific and waiting/checkpoint durations still require a **separately reviewed** additive instrumentation contract before a prospective hosted study can promise them. Synthetic wall times are not performance observations.

The post-run `m22_scoring.py` remains outside model execution: a separate independent-accepted answer envelope is required, version/digest/source/case matched; changed/draft/provisional answers fail closed. Per-case six-label and review-boundary agreement is **not semantic correctness**, and `formal_accuracy` stays `null`. `evaluation_m18.pinned_baseline` verifies the same case/run/deal/source/bundle when supported; missing, excluded and unsupported comparators are separate, never scored as improvement. Cohort denominators remain separate; no real held-out answers were created or exposed. Human approval/customer acceptance remain pending in the review, not inferred from AI. Any future independent semantic-scoring protocol is a separate gate.
