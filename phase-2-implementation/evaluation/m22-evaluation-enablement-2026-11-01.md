## WP1 — enforced *offline* campaign entrypoint

`backend/dealdesk_phase2/m22_enablement.py::OfflineCampaign` composes the WP2 write-once manifest/preflight and strict checkpoint/receipt reconciliation. `freeze(root, campaign_id, phase2_sha, cases, adapter)` must run before any eligible offline callback; `preflight` writes the frozen one-time eligible/ineligible/source-failure marker. `execute_offline(case_id, observed_identity=..., execute=...)` checks independent manifest SHA, campaign/Phase 2/Phase 1C identities, exact case, all source/run/bundle fields and declared capture/model/prompt contracts; it requires eligible preflight and atomically creates an owner-only write-once **start marker before** invoking the offline model-double callback. An unknown send, callback exception or crash cannot be replayed with the same case/assessment even after a new process opens the manifest. The callback must return a stored `(state, checkpoint_pending)` and is strictly reconciled with frozen identity. `report(checkpoints=..., receipt_root=...)` keeps all scheduled cases and cohorts; when a start marker exists without a checkpoint, it adds `started_without_checkpoint_unknown_send` rather than fabricating provider delivery or an attempt count. A caller-supplied checkpoint with no start marker fails closed. The existing registry report includes source/run/bundle/contract identities per case for offline scoring; existing counts remain reservation-based. Bounded receipt audit checks only receipt-bearing transports when caller supplies an explicitly approved owner root; no unreturned delivery is inferred.

The five existing six-stage mocked-transport fixtures in `test_m21_hosted_gate.py` now actually invoke this gate before `_six_campaign`, compare its post-run result to WP2 reconciliation and check wall measurement. Tests exercise an absent/rejected preflight, wrong case/hash, changed manifest, crash/timeout, restart without re-execution, unstarted scheduled rows and unsupported receipt transports. The existing opt-in historical hosted CLI and sender contracts were **not** modified. This is an offline entrypoint, **not** enforcement over arbitrary callers or the old hosted CLI. Before an authorized prospective hosted study, integrate the same pre-send gate with the reviewed sender entrypoints and ensure independent out-of-band preservation of the manifest digest/actor authorization. File digests and modes defend against accidental change, not a privileged owner replacing all artifacts. Separate source-first acceptance and quota authorization still required.

## WP2 — measured only, with missing values retained

`OfflineCampaign` measures monotonic end-to-end wall duration across its offline callback including any waits; the completed measurement is stored write-once in an owner-only, manifest-bound sidecar and checked on restart. `MeasuredIntervals.measure` can bracket named sequential specialist/original-graph/review and rate/local-quota spans, including failures. `timing_observation` reports each present span, explicit `null` for unmeasured stages, each stored attempt's actually reported elapsed and prompt/completion tokens or `null`, plus optional caller-*measured* checkpoint elapsed. No subtraction from wall time claims orchestration overhead, no inferred wait, total tokens, USD cost, typed-final provider elapsed or historical timing. On crash before a final timestamp, elapsed stays unavailable; report/restart do not synthesize missing timing. Stage spans are opt-in **inside the evaluation callback**, not invasive edits to the historical checkpoint, receipt or parallel graph. To complete six-stage hosted wall-time analysis the separately authorized runner must instrument actual stage boundaries and report nulls for uninstrumented provider/graph intervals. Clock values and synthetic fixture timings are not hosted measurements.

## WP3 — post-run source-first scorer and matched fixed comparator

`m22_scoring.py` accepts a *separate* `m22-source-first-answers-v1` object with exact registered case membership and source identities, `independent_accepted` status and reviewer/source-check attestation plus digest of answer cases. Draft/provisional/developer-supervisor statuses and changed content fail **before** case scoring. This is an offline contract assertion, **not authentication or issuance of accepted Phase 1C answers**: a trusted answer owner must validate acceptance, independently preserve the digest and keep the file completely inaccessible to specialists and model prompts. No real 36-case answer is created here. Tests use synthetic `fault_injection` labels only.

The scorer compares six pinned fixed findings and allowable six original AI execution labels (including abstention) per case, labels mismatches, distinguishes missing observations from not-assessable outcomes, and checks human-only reviewer action, review status and pending candidate customer acceptance. A candidate with unknown reference eligibility is not scored as an absence/presence success. Its `formal_accuracy` is **always null**: execution-label agreement is not proof of semantic correctness, evidence-grounded citations or a favorable reviewed deal. Independently accepted case-level semantic adjudication and an approved accuracy rubric still need to be specified before formal scoring. An eligible baseline requires exact `m1.8-pinned-baseline-v1` from `evaluation_m18.pinned_baseline` with same original run, deal, selected source digest and bundle as the AI checkpoint; changed evidence fails closed. A declared exclusion or unsupported baseline capability remains labelled `excluded`/`unsupported`, never an AI win. All comparisons remain per case and cohort. `reports` produces JSON and Markdown with missing/unsupported counts; no scored answer, baseline or draft is passed into the assessment callback.

**Example:** B01 may propose an eight-now/two-confirmed-inbound schedule. Six candidate fixed checks verify only supported *unreserved* supply; the human reviewer still sees a pending customer date change. The runner can capture its checkpoint/receipts without a second send. A later independently accepted answer could compare its six original findings and human-review action with same-source deterministic discovery; copying that discovery is not incremental value. The fixture is not a formal B01 score.
