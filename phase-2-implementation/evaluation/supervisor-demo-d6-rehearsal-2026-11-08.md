## Dependency and security decision

Re-ran `npm audit --json`, `npm audit --omit=dev --json` and `pip-audit -r backend/requirements-m1.1.lock --format json` against the pinned lockfiles. **No compatible low-risk patch was available for the affected paths without changing the approved framework/development architecture; no advisory was silently suppressed.** The application must remain loopback-only. Advisories apply to the pinned dependencies even where a particular vulnerable component is not invoked by this app.

| Finding | Affected component / exploit precondition | Current containment / disposition |
| --- | --- | --- |
| `GHSA-g3hv-75wg-m249` and seven derivative audit nodes (8 moderate dev advisories total) | `minimatch@10.2.6` under `typescript-eslint`/`eslint-config-next` and related eslint-plugin/parser/utils graph. Globparts amplification requires processing a crafted glob/pattern in developer lint/type tooling, not a user-controlled HTTP request in this app. | `npm audit --omit=dev` has **zero** production advisories. The newest compatible `minimatch@10` in the registry is 10.2.6; patched version begins 11.0.1 and ESLint config tooling still requires major 10. `npm audit fix` proposes an incompatible `eslint-config-next` 15.x downgrade. Do not lint untrusted trees; defer dependency migration until a compatible, tested upstream release. |
| `PYSEC-2026-1941` | Starlette multipart large-file spooling blocks the event loop when an app parses large uploaded files. | No upload/form endpoint; bounded 512-byte POST, local listener. Patch ≥0.47.2 exceeds `fastapi==0.115.12`'s `starlette<0.47.0`. |
| `PYSEC-2026-1942` | Starlette `FileResponse` HTTP multi-range parsing CPU exhaustion when files are served to an attacker. | No static/FileResponse route; local listener. Patch ≥0.49.1 not compatible with pinned FastAPI. |
| `PYSEC-2026-161` | Unvalidated Host can produce a misleading reconstructed `request.url` when authorization logic trusts that URL. | API middleware requires exact `127.0.0.1:8765`; auth uses bearer/owner, not reconstructed URL. Patch ≥1.0.1 requires framework review. |
| `PYSEC-2026-2280` | A Starlette `HTTPEndpoint` route with unrestricted methods and crafted HTTP verb may dispatch an unintended attribute. | App registers only FastAPI function routes with explicit GET/POST; no `HTTPEndpoint` subclass. Patch ≥1.1.0. |
| `PYSEC-2026-2281` | Starlette `StaticFiles` on **Windows** could resolve an attacker-controlled UNC path and leak a service account's NTLM credentials over SMB. | Demo runs on Linux, no StaticFiles endpoint. Patch ≥1.1.0. |
| `PYSEC-2026-248` | Malformed path may change a reconstructed URL's apparent host if code uses `request.url.hostname` for security decisions. | App uses bearer auth + exact raw Host, not reconstructed URL; local binding. Patch ≥1.3.0. |
| `PYSEC-2026-249` | Starlette form `max_fields`/`max_part_size` ignored for urlencoded bodies where an app calls `request.form()`. | Only strict bounded JSON POST; no form parser. Patch ≥1.3.1. |

`pip-audit` reports **14 records for seven distinct Starlette IDs** (duplicates in the advisory feed). `fastapi==0.115.12` requires `starlette>=0.40.0,<0.47.0`; the higher Starlette fixes require a separately approved FastAPI/framework upgrade and full compatibility testing. Do **not** try to override the resolver constraint. Loopback binding, no proxy/tunnel, strict request validation, generic error messages and no unsafe exposed routes reduce reachable attack surfaces but do not remove the dependency risk or justify production use. Session limitations (no per-user rate limiting/server-side revocation; HTTP cookie `Secure=false`) remain as documented in D5/D4. No keys or provider settings were changed.
