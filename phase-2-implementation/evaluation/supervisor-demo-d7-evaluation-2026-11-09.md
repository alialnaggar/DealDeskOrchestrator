## Threats to validity and remaining evidence

**Internal validity:** assertions compare actual API DTOs against pinned synthetic fixtures and source/subject identities; scripted outputs make the walkthrough repeatable but cannot show how a stochastic hosted model would choose or phrase a proposal. D1 targeted tests, D5/D6 broad suites and browser runs share some test code/cases and must not be treated as statistically independent repetitions. Failure injection mutates only disposable sources, not production records; not every possible interrupt instruction or PostgreSQL failure was tested.

**Construct/external validity:** `needs_revision`, unreserved supply and withheld routing are real outputs of this *fixture and fixed verifier*, not a measurement of deal resolution for arbitrary customers. The 36 held-out cases lack independently accepted answer keys; specialist accuracy, precision/recall, useful-candidate rate, comparative value versus fixed-only rules and model reliability remain **unmeasured**. No latency/cost/model-performance measurements were collected for this demonstration. The UI does not accept new deal data, customer terms or a second candidate; no stock reservation, customer acceptance, final human approval or production integration exists.

**Security/deployment validity:** a local single-operator HTTP session, loopback-only services, and known residual `Starlette` advisories (seven distinct IDs, 14 report records) plus eight moderate development-only npm findings are [catalogued in D6](supervisor-demo-d6-rehearsal-2026-11-08.md). npm production audit found zero advisories at D6. Reachability mitigations are not patches; no public TLS, remote authentication, security certification or broad load/DoS claim follows. Browser/mobile and keyboard checks are not a full independent assistive-technology audit. Formal evaluation requires independent accepted case answers, a predeclared metric/baseline protocol, answer isolation and approved provider access if later tested; none is implied by this report.
