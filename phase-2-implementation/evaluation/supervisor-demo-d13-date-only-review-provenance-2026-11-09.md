# D13 — date-only author provenance and protocol-deviation notice

**Infrastructure only. No review decisions or reference answers are in this file.** D11 first-pass JSON `schema_version: 2` adds `reviewer.review_date` (strict `YYYY-MM-DD`) and `reviewer.review_timezone` (IANA zone, e.g. `Africa/Cairo`). A genuine review without a recorded clock time uses both fields and sets `reviewer.reviewed_at: null`. This is **date-only provenance**: the system does not infer a clock time, UTC instant or ordering within that day. An independently recorded file-entry or freeze timestamp is **not** the review time. The validator refuses invalid calendar dates/zones and a simultaneous precise `reviewed_at` plus date-only fields.

Schema-version 1 forms and freeze receipts remain valid with their existing timezone-aware `reviewed_at`; version 2 can also use a precise timezone-aware `reviewed_at` if the date-only fields are null. Version 2 freeze receipts bind the date and zone (or the precise time, when supplied) alongside the exact form digest, but a receipt is not an identity attestation, independent review or acceptance. Completed author findings remain private in the separate D11 workspace. D11 structural validation does **not** make its date-only form compatible with the authoritative Phase 1C v2 intake, which still requires a timezone-aware `reviewed_at`. **Before any Phase 1C acceptance**, obtain a separately approved, versioned intake adaptation or an independently documented true review timestamp; never convert the record-entry/freeze time into a claimed review time.

This is not a claim of zero exposure or independent/blinded review. The current work restricts execution to `test_d11_human_review.py`; D10 tests, dossier reading, comparison and unlock are excluded.
