**Exact reproducibility path.** Use the [D6 runbook](../planning/supervisor-demo-d6-offline-runbook.md) from a checkout of `supervisor-demo-offline-v1` with its **separately pinned Phase 1C checkout**, local locked dependencies, an approved disposable PostgreSQL 16 cluster, a *new* setup env filename and owner-only generated secrets. It gives exact setup/startup/test commands. Do not run any historical hosted development CLI. Run `git rev-parse supervisor-demo-offline-v1^{}` and `git -C /tmp/opencode/dealdesk-phase1c-pinned rev-parse HEAD`; verify lock hashes with `sha256sum`. No secret, database dump, original checkpoint, browser token or private ledger is in the tag/documentation. Dynamic assessment IDs, event timestamps and synthetic database names are expected to vary; 21/20 event counts and the checked DTO semantics are the assertions for these two fixture variants, not a guarantee for future runtime versions.

**What “reproducible” means here:** another authorized operator with the same pinned source, dependency locks and disposable local environment can execute *new* offline scripted assessments and test the invariant outcomes. A Git tag alone does **not** freeze the VM, PostgreSQL cluster, installed browser binaries or local secrets; their prerequisites and differences are explicit in the runbook. Local screenshots/logs under `/tmp/opencode` are dated D5/D6 evidence, not version-controlled benchmark artefacts. This baseline is intentionally not an accuracy, latency, provider-reliability, production-security or deployment certification. The 36 held-out cases have **not** been independently accepted; specialist accuracy is unavailable.
