`backend/dealdesk_phase2/m22_evidence_gaps.py` defines typed `EvidenceGapV1` (`m22-evidence-gap-v1`) and a `m22-evidence-review-v1` projection. Every gap carries assessment/run, original or fixed-checked candidate subject, frozen bundle/input digests and cutoff, specialist, exact requirement/optional field, line/rule/source where established, scope/basis, reason, independent verification status, allowlisted impact/authorized human follow-up text and codes, and `unresolved` resolution status. `verified` is only a *bounded fixed diagnostic*, not proof of global record absence; `interface_limit` cannot assert a missing business record. Explicit model suggestions are accepted **only** for an existing original fixed gap, with any citation present in an actually returned authorized specialist tool record (and the right line); they remain `suggested_unverified`. Unsupported requirements, wrong-source references, duplicate or extraneous suggestion fields fail closed. The six fixed and original AI result shapes have not been changed; no model is prompted for gap output.

| Specialist | Demonstrated bounded report | Unverifiable under this pin |
| --- | --- | --- |
| Configuration | Fixed `compatibility.status=unknown` with exact fixed rule ID where present. | A missing BOM or compatibility record outside the selected pool is **not** established. A valid configuration produces no invented compatibility gap. |
| Pricing | Fixed `assembly_cost_disagreement` as a conflict; does not recompute price or cost. | Other or unnamed cost requirements cannot be inferred; unfamiliar fixed diagnostic fails closed. |
| Fulfillment | Fixed line `unknown`, `pending_production_check` (incomplete), `conditional`/`feasible_uncommitted` (unconfirmed), and independent `installation=unknown`, with exact line ID. | A supplier offer is not confirmed supply; no delivery date or global absence can be inferred from an uninspected pool. |
| Credit | Fixed `commitments_fresh=False`: dated selected profile ref and stale field for original; no candidate source ref is borrowed. Ledger-completeness **interface limit** separately reported beside a valid finding or abstention. | A zero-valued receivable and an empty selected list are **both** insufficient to prove a complete-zero AR/payment scope; neither clears Credit. |
| Policy | Per-rule prerequisite **interface limit** from fixed `per_rule_prerequisites_available=False`. | No invented missing policy document, rule non-hit or waiver; hard blocks remain fixed. |
| Approval Routing | Withheld route/roles **interface limit**, or verified skipped prerequisite. | Required roles cannot be named while withheld; no AI approval. |

`project_gap_review` first checks the historical checkpoint using `capture_m22` (including six original and optional six fixed-checked candidate results, subject binding, citations and review integrity) and revalidates the pinned pool. It deep-copies the governed reviewer package, adds gaps under each original fixed specialist and under each **separately checked candidate** fixed specialist if present, retains the original AI finding/abstention/reviewer action and appends separately marked original-only AI suggestions. It labels the new projection version and historical base version; **it does not rewrite the checkpoint, send a model request, or silently reinterpret historical `m1.7-review-v1` packages.** The same projection is reconstructed after PostgreSQL restart. A skipped fixed specialist gets an unmet-prerequisite report; a fixed execution error gets an interface-unavailable report, never an empty implied pass. Valid findings can coexist with fixed gaps and an abstention can coexist with stale Credit.

**Independent review correction:** An unverified suggestion may cite a returned record **only** when it is the exact source reference established for that fixed gap (and belongs to the correct specialist/line); an unrelated returned receivable cannot be cited as the source of stale commitments. Fixed `feasible_uncommitted` and independent unknown installation eligibility are reported even when another Fulfillment field is confirmed. Neither correction grants supply or approval authority.

**Offline negative controls:** `test_m22_evidence_gaps.py` covers all six present/absent/conditional fixed diagnostics, valid finding with gaps, explicit-zero versus empty Credit selection, stale original vs candidate isolation, conflicting cost, incomplete delivery, valid abstention with a separate unverified suggestion, unknown requirement, bad citation, wrong-specialist suggestion, spoofed verification field and wrong credit customer. The existing `test_m21_hosted_gate.py` six-stage candidate/no-candidate variants compare the complete projected review across PostgreSQL restart and prove the historical package and six fixed results are unchanged. Existing WP1/WP2 tests cover forged source/subject, receipts and no-replay separately. No new UI, evidence intake or candidate reassessment was added.

**Example:** An N01/UC02-style Credit case with dated but stale commitments retains its fixed `unknown` and the offline model's valid abstention; the reviewer sees the verified stale profile field and a *separate* unresolved ledger-completeness interface limit. The next human action is to request dated commitments and ask the source owner about a trusted completeness interface, not to assume zero debt or authorize a deal. An alternative B01 schedule is displayed only with its independently fixed-checked candidate findings; the original remains unchanged.

WP4 needs separate source-owner/API and security approval, versioned evidence, new assessment identity and a full rerun; no old uncertain request may be replayed.
