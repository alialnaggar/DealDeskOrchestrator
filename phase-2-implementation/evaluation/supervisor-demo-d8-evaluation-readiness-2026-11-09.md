## Reviewer procedure (requires supervisor methodology decision)

1. **Before predictions:** agree who may be accountable (author versus independent reviewer), whether a second-model or independent-human pass is required, what Credit v3 scope counts as complete, the candidate/cohort eligibility protocol and an accepted reference version. No supervisor approval or independent review is implied here. Keep source/review material in a reviewer-only checkout, not the demo runtime, model prompts, tools, logs or development samples. Preserve the current index/source SHA and source-only packet/provider files from a matching export; stop on hash drift, version the new source rather than editing old answers in place.
2. **Source-first blinded pass:** open each original submitted deal, `run_context`, `source_rows` (catalogue/BOM/compatibility; price/cost and commercial rules; inventory, receipts, offers, production, digital/provider and service/lane facts; credit profile/AR/payments; policy/routing), separate provider records, business contract and dated as-of. Record calculations, both positive and contrary evidence, missing/stale/unknown facts and **six** independent responsibility codes/rationales with resolvable `/source_rows/`, `/run_context/`, `/business_contract/` or `/records/` JSON pointers; record whole-deal precedence, human actions and unresolved questions. Empty `records` needs a scope/completeness explanation. Do not look at model predictions, draft answers, authoring archetypes or deterministic baseline outputs first. The existing blank template and source-first handbook already supply the fields. The blinded handbook is AI-assisted and cannot by itself establish independent human labels.
3. **Review, then adjudicate:** freeze a dated first-pass snapshot and SHA before consulting original model draft, author amendment, 216-item technical matrix or rule-only output. Record every disagreement, changed citation, counterexample, assistance disclosure and unresolved source issue; reject/defer when needed. `draft_complete` means structurally filled, not reviewed; `reviewed_pending_disposition` means a distinct source-first record exists; `accepted` needs explicit dated human adjudicator, reason and assistance disclosure in the existing Phase 1C intake **after** a preserved reviewed predecessor. The original decision cannot be overwritten; corrections require a separately versioned history. Author-conducted acceptance must be labelled *author adjudication*, not independent expert agreement.
4. **Eligibility and release:** only a case accepted under the explicitly approved source-version/methodology gate is scoreable; reviewers and supervisor resolve disagreements before unlocking predictions. Keep 039–041 separate; never import the author manifest, expected findings or accepted intake into the API/UI or prompts. The Phase 1C release flag remains false until its other gates are independently met. Record packet/index/credit-scope hashes, cohort, phase pins, model/prompt versions and one prospective campaign manifest **before** any separately authorized AI trial. No hosted/paid call is authorized by D8.

## Read-only validator and report generator

[`d8_readiness.py`](d8_readiness.py) imports the **existing Phase 1C** review/intake validators from a separate checkout. It pins the exact 36-case index, validates blank/filled forms, packet/provider hashes and permitted source JSON pointers through that code, rejects unknown/duplicate/missing cases, invalid findings, metadata and source drift, and rejects direct pending→accepted, changed accepted records or acceptance without a preserved validated reviewed predecessor. It scans declared model-visible paths for held-out IDs and refuses reviewer files inside them. This is a *conservative local leakage check*, **not** proof against paraphrases, other prompt roots or earlier hosted sends; the reviewer must audit actual serialized prompts/tool records. It reads no authoring archetype or model draft, never writes or accepts an answer and cannot prove a human's claimed identity or correctness. Its `--intake`, `--prior-intake`, `--review-file` and `--packet-directory` point to existing private material; **do not commit them or the stdout report with answer contents**.

From the repo root, with a separately checked-out Phase 1C review tree containing the authoritative intake code (not the old demo pin), run:

```sh
python3 phase-2-implementation/evaluation/d8_readiness.py --review-root /path/to/phase1c-review-checkout
python3 -m unittest discover -s phase-2-implementation/evaluation -p 'test_d8_readiness.py' -v
```

The second command requires `DEALDESK_PHASE1C_REVIEW_CHECKOUT=/path/to/phase1c-review-checkout` outside this machine. For later **actual** reviews add `--review-file /private/source-first.json --packet-directory /private/matching-packets --intake /private/intake.json --prior-intake /private/previous-intake.json`; validate all transitions and scope/version before any scoring. `--run` accepts a **prospective** JSON object with exact keys `mode`, `model_version`, `prompt_contract`, `dataset_index_sha256`, `phase2_commit`, `campaign_id`, `cases`; cases must list all 36 unique IDs with `status` in `completed/abstained/failed/skipped`; a completed accepted case requires six named finding codes and `overall` gate. This simple JSON contract cannot verify genuine provider delivery, semantic citations or costs: reconcile external M2.2 manifest/receipts and audit actual prompt isolation independently. **Never relabel a scripted run `genuine_ai`**. If accepted references are empty or mode is `offline_scripted`, all accuracy cells stay `null` even when a run is supplied. No illustrative score is saved in the repository. The tool's current scoring is strictly the **v2** index; a v3 Credit source/version or 039–041 needs separately extended intake, scope binding and approved protocol before formal scoring.

## Predeclared metrics and denominator rules (not results)

Use one scheduled original case as the **unit**; keep repeated attempts nested under case and keep cohorts/versions separate. Preserve all 36 scheduled cases including ineligible/failed/skipped with a predeclared reason. Never impute abstention or unknown as correct without an accepted reference that explicitly allows it. A zero denominator yields `null` plus its count, never 0% or 100%. The D8 script computes only the few *structural exact-match* quantities below when accepted v2 records and an explicitly labelled prospective genuine-AI run exist; the remainder require additional captured fields, independent human review or instrumentation.

| Quantity (future) | Numerator / denominator; exclusions and interpretation |
| --- | --- |
| Per-specialist finding agreement | Exact matching named finding code / accepted cases with **completed validated output for that specialist**; show missing, abstained, errored and unsupported codes separately; report each specialist's `n`, not six cases per deal. D8 currently scores only complete six-slot outputs and marks the others unscored. Compare qualitative rationale separately by blinded humans; code equality is not semantic correctness. |
| Overall gate agreement | Exact whole-deal gate / accepted cases with valid completed whole-deal outputs; include all scheduled/eligible nonoutputs in separate coverage, never discard them silently. Gate precedence and required human action must also be reviewed, not inferred from a matching string. |
| Abstention, unknown and coverage | Abstentions / all eligible scheduled specialist opportunities (and case-level / all scheduled cases), explicit `unknown` fixed or AI evidence statuses / same predeclared opportunities; distinguish missing/error/skipped. Coverage = completed valid predictions / scheduled cases and / accepted eligible cases, with both denominators shown. D8 currently exposes case-level status counts only; specialist-level abstention/unknown rates are **unavailable** without a typed per-slot capture. |
| False clearance | Predictions claiming an executable approval/clearance or `approval_required` when an accepted source reference says `blocked` / accepted **blocked** cases with an evaluated output; list attempted/failed/abstained blocked cases separately.
