# M1.4 provider connectivity diagnostic — 20 October 2026

**Scope:** Owner-approved bounded diagnostics; no model change, new dependency, paid tier, Phase 1C modification or paired benchmark. Model IDs remained Groq `openai/gpt-oss-120b` and Gemini `gemini-3.8-flash`. The [first probe](https://github.com/alialnaggar/DealDeskOrchestrator/actions/runs/39484385679) ran at Phase 2 commit `8d2a15b`; the [configuration follow-up](https://github.com/alialnaggar/DealDeskOrchestrator/actions/runs/39484897793) ran at `3d0b4f6`. The dedicated workflow only runs on an explicitly pushed `phase2-m14-diagnostic-run` branch and does not invoke the paired benchmark. Both secret variables were nonempty; values and sensitive headers were not logged.

The 503 bodies said the model was experiencing high demand. None of the Gemini probes yielded content, structured JSON or a function call. The metadata response confirms the exact model is visible to this key; it does not prove generation availability. No tool was actually executed, no business evidence sent, and no Fulfillment result was accepted. This diagnostic did not collect usage tokens or account billing data. Its timings are request latencies, including 20-second client timeouts, and are not a paired Fulfillment latency comparison. Request IDs were recorded when exposed by Groq; the sampled Gemini responses did not provide an allowlisted request ID.

**Cause and fix:** Cloudflare documents error 1010 as a browser/client signature block. The only intentional change between Groq probes was adding a truthful `DealDeskOrchestrator-thesis-M1.4/1.0` User-Agent; the same key, endpoint and model then succeeded. The live adapter now sends that header. This is observed connectivity behavior, not proof of the exact server-side filtering rule. Google rejected `additionalProperties` in `generateContent.responseSchema`. The Gemini adapter now projects the schema onto accepted fields and keeps strict local output validation; an offline test checks this projection. Repeated Gemini 503 and timeouts prevented a successful live retest of the projected schema. Google documents 503 as a transient overload class.

**Next gate:** Keep the model IDs unchanged. Run one eligible pinned Fulfillment smoke for Groq with the corrected adapter. Retry Gemini's separate generation, structured and tool probes after service recovery within the existing free-tier and request limits; if it continues failing, investigate provider availability through Google support/status without enabling billing or silently switching models. Only after both models produce validated Fulfillment outputs should the gated paired repetitions run. There is no quality winner yet.
