## Failed-attempt increment — 21 October 2026

`persist_development_attempt` owns a single transaction and requires an idle connection. On a successful replay it commits the existing seven envelopes. If the reader, decision adapter or output validation fails, it rolls back that transaction and commits one `Failed` Orchestrator attempt with the frozen run identity and exception **class only**. The run becomes `failed`; no partial success output or retry is recorded. An already terminal run is rejected, and there is no automatic retry or side effect. This wrapper is limited to deterministic development execution and does not turn a failure into a business finding.

The PostgreSQL integration test injects an invalid output contract into the real execution path, then reads the failed row and run status through a separate connection to prove commit visibility. It checks that no specialist success row or `output_json` survives and that repeating the attempt is rejected. It cleans up its disposable run afterward. This tests committed failure bookkeeping on CI PostgreSQL, not process-crash recovery, concurrency, production durability or AI specialist failure handling. The output field mark stays open.
